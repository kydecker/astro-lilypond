`lilypondLoader()`, imported from `astro-lilypond/loader`, accepts the following options.

## Options

### `base`

**Type:** `string | URL`  
**Required:** yes

The directory `pattern` resolves from. Relative to the project root.

### `pattern`

**Type:** `string | string[]`  
**Default:** `"**/*.{ly,ily,lilypond}"`

Glob pattern(s) matching score files, relative to `base`.

### `generateId`

**Type:** `(options: { entry: string; base: URL; header: Record<string, string> }) => string`  
**Default:** the file's path relative to `base`, with its extension stripped (e.g. `preludes/prelude-1.ly` becomes `preludes/prelude-1`).

Generates each entry's collection id. `header` is the file's parsed `\header` fields, so you can key ids off metadata instead of the file path if you'd like.

### `defaults`

**Type:** `object`  
**Default:** same as the [integration's `defaults`](/reference/configuration/#defaults)

Used when [`render()`](/reference/render/) is later called on one of this collection's entries.

### `timeout`

**Type:** `number`  
**Default:** `60000`

Milliseconds to wait for a single `lilypond` invocation before aborting, when `render()` is later called on one of this collection's entries.

### `autoInstall`

**Type:** `boolean | { version?: string }`  
**Default:** `true`

Same as the integration's [`autoInstall`](/reference/configuration/#autoinstall). `lilypondLoader()` resolves its own `lilypond` binary independently, so a collection works even without the `lilypond()` integration registered.

## `LilypondCollectionEntry` type

Each collection entry's `data` **is** a `LilypondScore` — the exact same lazy handle a plain `.ly` import gives you, header metadata included. Nothing is rendered until you call `render()` on it.

```ts
interface LilypondCollectionEntry {
  // Lazy handle fields — pass entry.data directly to render()
  source: string;
  alt: string;
  sourceName?: string;
  includePaths: string[];
  assetTitle: string;

  // Fields parsed from the file's \header block(s) — see LilypondMetadata
  // in the render() reference. Same shape a plain .ly import's meta has.
  meta: LilypondMetadata;
}
```

Call [`render()`](/reference/render/) on `entry.data`, exactly as you would a plain `.ly` import:

```astro {6} title="MyScore.astro"
---
import { getEntry } from "astro:content";
import { render } from "astro-lilypond";

const entry = await getEntry("scores", "my-score");
const { Score, meta } = await render(entry.data);
---

<h3>{meta.title}</h3>
<Score />
```

See [rendering a PDF download](/guides/collections/#rendering-a-pdf-download) for using `pdf: true` with a collection entry.
